This one looked like a geometry problem and turned out to be a sorting problem in disguise. Classic Codeforces misdirection.

## The problem

You're given `n` points. You may add **one** new point. Count how many of the original points could, after that addition, lie on a line of slope `1` or slope `-1` passing through the new point.

## The key observation

A point `(x, y)` lies on a slope-1 line defined by `y - x = c`, and on a slope--1 line defined by `y + x = c`. So every point belongs to exactly one "diagonal" in each direction, keyed by `y - x` and `y + x`.

The new point sits at some `(px, py)`. A point is reachable from it iff it shares either the `py - px` diagonal or the `py + px` diagonal.

## The sweep

So the answer for a candidate new point is: `(count of points with the same y - x) + (count with the same y + x) − (overlap)`. Group points into two hash maps keyed by those two values, and the best answer is just the largest combined bucket.

```python
from collections import Counter

diff = Counter(y - x for x, y in pts)  # slope +1 diagonals
summ = Counter(y + x for x, y in pts)  # slope -1 diagonals
ans = max(max(diff.values()), max(summ.values()))
```

## Where I lost time

I spent ten minutes trying to reason about *actual lines and intersections* before realizing the two diagonal keys collapse the whole thing into counting. The lesson I keep re-learning: when a problem mentions slope ±1, reach for `x ± y` before you reach for geometry.
